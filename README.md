# BilimGo

Каталог учебных центров и курсов Самарканда: поиск, карта города,
профили центров с курсами и заявкой на курс, избранное и сравнение.
Три языка интерфейса (русский, узбекский латиницей, английский), светлая и
тёмная тема. Данные и заявки — в Supabase, редактирование — в админке
`/admin`. Без Supabase сайт работает на встроенном снимке данных.

```bash
npm install
npm run dev                  # http://localhost:5173
npm run typecheck            # tsc --noEmit
npm run build                # typecheck + production build
```

Без переменных окружения сайт работает на встроенном снимке
(`src/data/centers.ts`), админка выключена. Подключение Supabase — ниже.

## Supabase и админка

1. Создайте проект на [supabase.com](https://supabase.com).
2. **SQL Editor** → выполните `supabase/schema.sql`: таблицы `centers`,
   `submissions`, `leads`, `admins`, RLS-политики, бакет `media` для логотипов
   и фото. Скрипт можно запускать повторно: в базах, созданных раньше, он
   добавит таблицу `leads` и переведёт адрес и тексты центров в формат трёх
   языков (старые строки становятся русским текстом).
3. Скопируйте `.env.example` в `.env.local` и заполните `VITE_SUPABASE_URL` и
   `VITE_SUPABASE_ANON_KEY` (Project Settings → API). `.env.local` в Git не попадает.
4. Перенесите 30 центров из снимка (один раз; нужен `SUPABASE_SERVICE_ROLE_KEY`
   в `.env.local` — только на вашей машине):

   ```bash
   node --env-file=.env.local supabase/seed-centers.mjs
   ```

5. **Authentication → Users → Add user** — создайте аккаунт администратора и
   выполните запрос из конца `schema.sql`, подставив его почту.
6. Откройте `/admin` и войдите.

Что где:

| | |
| --- | --- |
| `/admin/centers` | Все центры (и скрытые), поиск, «Новый центр» |
| `/admin/centers/:id` | Редактор: основное, точка на карте, направления, контакты и часы (с предпросмотром), описание и программы, для кого и формат, логотип и фото (сжимаются в браузере до WebP), цена и рейтинг, источники; «Показывать на сайте», удаление |
| `/admin/submissions` | «Новые центры» — заявки с `/add-center`: «Создать центр» (форма заполняется из заявки), «Отклонить», «Удалить» для спама |
| `/admin/leads` | «Заявки на курсы» со страниц центров: курс, телефон, имя, комментарий; «Обработано», «Спам», «Удалить» |

Адрес и тексты (коротко, «О центре», программы, «для кого», подписи к фото)
редактируются на трёх языках: переключатель «Тексты RU / UZ / EN» в шапке
редактора. Русский обязателен, узбекский и английский, если пусты, берутся
из русского.

Безопасность и правила данных:

- Anon key публичен по замыслу: писать может только пользователь из
  `public.admins` — это проверяют RLS-политики в базе, а не интерфейс.
- Посетитель может только создать заявку и не может её прочитать. Лимиты в
  базе: заявок на добавление центра не больше 30 в час на сайт, заявок на
  курс — 60 в час на сайт и 3 в час с одного номера. В обеих формах есть
  ловушка для ботов.
- Цена и рейтинг сохраняются только со ссылкой на источник (проверка и в
  форме, и в базе), фото — только с автором, лицензией и источником.
- Публичный сайт читает данные двумя REST-запросами без SDK: Supabase JS
  грузится только в чанке админки.
- Дата правки записи (`updated_at`) на сайте не показывается; в админке она
  видна в списке центров.
- Раздел «Преподаватели» в профиле центра: имя, что преподаёт, строка из
  источника и портрет (с автором и ссылкой на источник). Без добавленных
  преподавателей раздел показывает пустые рамки и пояснение. Список
  редактируется в админке; в базе это колонка `centers.teachers` (jsonb).
- Блок «Как проходят занятия» (`centers.lessons`, jsonb): короткие факты —
  частота, длительность, размер группы, тест уровня. Только то, что центр
  пишет сам; в админке — по одному факту на строку.
- Блоки профиля появляются при прокрутке (`useReveal`, стили в `base.css`);
  при «уменьшить движение» показываются сразу.

## Админка (CRM)

`/admin` — рабочее место администратора. Разделы слева:

- **Дашборд** — что ждёт ответа, заявки по дням, какие центры заполнить в первую очередь.
- **Заявки на курсы** — список со статусами «Новая → В работе → Обработана / Спам»,
  поиск, фильтры по центру и периоду, панель заявки с заметкой, звонком и
  Telegram, массовые действия, выгрузка в CSV.
- **Новые центры** — заявки владельцев: проверка дублей, заметка, «Создать центр».
- **Центры** — таблица с заполненностью профиля, быстрым переключателем «На сайте»,
  массовыми действиями и «Создать по образцу» для нового филиала. В редакторе справа
  публикация, чек-лист заполненности и переходы по разделам.
- **Преподаватели** — все преподаватели каталога, заглушки и карточки без фото.
- **Медиатека** — загруженные файлы, где они используются, что можно удалить.
- **Настройки** — состояние базы, Telegram-бота и капчи, аккаунт.

Поиск по центрам, заявкам и разделам открывается по ⌘K / Ctrl+K. Для статусов
заявок и заметок в таблице `leads` есть колонки `note` и `handled_at`
(см. `supabase/schema.sql`, блок «для баз, созданных до CRM-админки»).

## Заявки на курсы и Telegram-бот

На странице центра есть раздел «Курсы и цены»: цены не публикуются, у каждого
курса кнопка «Узнать цену», в шапке — «Записаться». Обе открывают окно
заявки: курс, телефон (+998 и 9 цифр), имя и комментарий по желанию.
Куда уходит заявка, решает `src/services/leads.ts`, по первому подходящему
варианту:

1. **Свой адрес** — задайте `VITE_LEADS_URL` в `.env.local`. Сайт отправит
   `POST` с JSON:

   ```json
   { "center_id": "polyglot-gagarina", "center_name": "Polyglot Language School",
     "course": "IELTS Intensive", "name": "Азиз", "phone": "+998901234567",
     "comment": null, "locale": "uz", "page": "https://…/centers/polyglot-gagarina" }
   ```

   `course: null` — человек просит консультацию. Ваш сервер (например, бот на
   aiogram или n8n) должен отвечать на CORS-запросы с домена сайта; ответ
   `429` сайт покажет как «слишком много заявок». Токен бота держите на своём
   сервере: всё, что начинается с `VITE_`, попадает в браузер.

2. **Supabase** (если `VITE_LEADS_URL` не задан) — заявка записывается в
   таблицу `leads`, её видно в `/admin/leads`. Сразу после записи триггер
   `leads_notify` просит Edge Function `supabase/functions/lead-to-telegram`
   доставить её в Telegram. Функция берёт заявку из базы по номеру и
   помечает её `notified_at`, поэтому каждая заявка уходит один раз.

   1. Создайте бота: в Telegram откройте [@BotFather](https://t.me/BotFather),
      команда `/newbot`, получите токен.
   2. Откройте своего бота и нажмите **Start**. Первый, кто нажал Start,
      становится получателем: функция сама находит этот чат и запоминает его
      в таблице `bot_chat`. Для группы или другого человека задайте секрет
      `TELEGRAM_CHAT_ID`.
   3. Supabase → Edge Functions → Secrets: добавьте `TELEGRAM_BOT_TOKEN`.
      Токен живёт только здесь и в `.env` сайта не попадает.
   4. Отправьте тестовую заявку на сайте: она придёт в бота вместе с теми,
      что накопились до настройки (до 20 штук).

   Все заявки в любом случае видны в `/admin/leads`.

3. **Ничего не подключено** — форма проверяет поля и честно говорит, что
   приём заявок ещё не подключён, и предлагает позвонить в центр.

## Капча в формах

Формы «Узнать цену» / «Записаться» и «Добавить центр» можно защитить
[Cloudflare Turnstile](https://www.cloudflare.com/products/turnstile/)
(бесплатно, без картинок с светофорами). Без ключей формы работают как раньше.

1. Cloudflare → Turnstile → **Add widget**, домен вашего сайта, получите
   **Site key** и **Secret key**.
2. Site key (публичный) — в Vercel → Settings → Environment Variables:
   `VITE_TURNSTILE_SITE_KEY`, и в `.env.local`. Затем `npx vercel --prod`.
3. Secret key — только в Supabase → Edge Functions → Secrets:
   `TURNSTILE_SECRET_KEY`.
4. Функция `submit-form` проверяет токен у Cloudflare и только потом пишет
   заявку. Когда всё проверено, выполните `supabase/captcha.sql`: это закроет
   прямую запись в таблицы в обход капчи.

## Карта

Карта — [MapLibre GL JS](https://maplibre.org/) со стилем
[OpenFreeMap](https://openfreemap.org/) «liberty» (данные OpenStreetMap).
Сервис бесплатный и работает без ключа, поэтому секретов в проекте нет.
Библиотека грузится отдельным чанком только на экранах с картой.

Тема карты следует теме сайта: в тёмной — стиль OpenFreeMap «dark»,
перекрашенный под палитру BilimGo. Подписи улиц и районов — на языке
интерфейса (узбекский и английский — латиницей), если они есть в OSM.

При сетевой ошибке приложение продолжает работать: на месте карты — состояние
«Карта сейчас недоступна» с кнопками «Повторить» и «Открыть в OpenStreetMap»,
список и фильтры работают как обычно. Атрибуция OpenFreeMap / OpenMapTiles /
OpenStreetMap всегда видна на карте.

## Перед запуском

- Заявки «Добавить центр» при подключённом Supabase попадают в
  `/admin/submissions`. Без Supabase форма отправляет письмо на
  `SITE.partnerEmail` (`src/config/site.ts`), а если он пуст — копирует заявку
  в буфер обмена и говорит об этом.
- Без Supabase дата проверки данных — `DATA_CHECKED_AT` в `src/data/centers.ts`;
  обновляйте её вместе со снимком.

## Экраны

| Экран | Что умеет |
| --- | --- |
| **Главная** `/` | Заголовок с числом мест и районов из данных, поиск со «смысловым» разбором запроса («английский для детей на Гагарина»); «Популярные центры» — карусель с фото зданий снаружи (у сети без такого фото — знак на орнаменте) и две встречные ленты логотипов всех центров; направления; районы и превью карты; блок для представителей центров |
| **Поиск** `/search` | Desktop: список + карта с синхронным hover/выбором. Телефон и планшет: список, который прокручивается как страница (при возврате из профиля — на том же месте), и кнопка «На карте». Карточки нового ответа появляются по очереди; у самых популярных мест — значок «Популярный выбор» и золотая рамка, у сетей — число филиалов. Фильтры, сортировка (в т. ч. «По популярности»), исправление раскладки («шудеы» → «ielts»), состояния loading / empty / error |
| **Карта** `/map` | Полноэкранная карта: кластеры, места появляются волной от центра экрана, превью у маркера (desktop) или окно, которое выезжает снизу и закрывается смахиванием вниз (телефон), кнопка «Списком» с числом мест на том же месте, где в списке «На карте». Фильтры у списка и карты общие |
| **Профиль** `/centers/:id` | Название, тип и филиал, адрес и статус «открыто сейчас», «Записаться» и звонок, маршрут, фото или карта; «О центре», «Курсы и цены» — карточки курсов с «Узнать цену» и тёмный блок «Не знаете, какой курс выбрать?» с консультацией, для кого и формат, контакты и часы по дням, филиалы сети, источники, похожие места рядом. Кнопка «назад» подписана по месту, откуда пришли: «К карте», «К результатам», «К избранному»… |
| **Избранное** `/favorites` | Сохранённые места (localStorage), «Сравнить все», очистка с отменой |
| **Сравнение** `/compare` | До 4 мест в таблице: направления, адрес, часы, для кого, формат, программы, контакты. Ссылкой можно поделиться (`?ids=`) |
| **Добавить центр** `/add-center` | Форма заявки: название, адрес, телефон, ссылки, направления, контакт. См. «Перед запуском» |
| **Админка** `/admin` | См. «Supabase и админка»; закрыта от поисковиков (`noindex`) |

Язык (RU / UZ / EN) и тема (солнце / луна) — в шапке; выбор запоминается в
браузере, без выбора тема следует системной. Ссылку на нужный язык можно дать
параметром `?lang=uz`.

Все маршруты открываются напрямую и переживают обновление страницы. Для
статического хостинга нужен SPA-fallback на `index.html` (в `vite preview`
он уже есть).

## Данные

**30 адресов 18 популярных центров Самарканда** — `src/data/centers.ts`, дата
проверки `DATA_CHECKED_AT`.

- **Только популярные**: в каталоге сети, у которых на Яндекс Картах в сумме по
  филиалам не меньше 50 оценок (из 83 собранных мест осталось 30). Число оценок
  карточки хранится в `yandexRatingCount` и задаёт сортировку «По популярности»
  и порядок «Популярных центров» на главной; на сайте оно не показывается.
- **«Популярный выбор»** — значок у пяти мест каталога с наибольшим числом
  оценок на Яндекс Картах, по одному на сеть (`POPULAR_PICKS` в
  `centersRepository`). Это факт из карточек, а не оценка качества: слов
  «лучший» и выдуманных наград на сайте нет. Список пересчитывается сам, когда
  в каталоге меняются центры.

- **Базовые факты** — название, координаты, адрес, телефоны, часы работы и
  статус «работает» — из публичных карточек организаций на Яндекс Картах
  (`yandexId`; ссылка на карточку есть в профиле).
- **Направления, программы и описания** — с официальных сайтов и официальных
  Telegram-каналов центров (`sources` у каждой записи). Тексты переписаны
  своими словами, без копирования. Там, где организация сама указала на
  Яндекс Картах языки, возраст учеников и формат, — используются и они.
- **Логотипы** — собственные знаки центров с их официальных сайтов,
  Telegram-каналов и Instagram (`public/media/logos`). У Gutenberg и Global
  Language Centre официальных каналов нет — у них типографическая монограмма.
- **Фото** — только с официальных сайтов и Telegram-каналов центров
  (`public/media/photos`, WebP до 1280 px) и только у того филиала, где они
  сняты. У каждого фото — владелец, ссылка на публикацию и пометка, снаружи
  здание или внутри (`view`): карусель на главной берёт фото снаружи. Фото
  принадлежат центрам: если центр попросит, снимок убирается. Снимки с Яндекс
  Карт не используются (условия Яндекса), сертификаты и документы с личными
  данными учеников — тоже. В профиле фото идут слайдшоу; без фото главное
  изображение — карта.
- **Три языка** — описания, программы, «для кого» и подписи к фото написаны
  по-русски, по-узбекски и по-английски. Адреса — как на Яндекс Картах
  по-русски, в узбекской и английской версиях улица записана латиницей
  (Gagarin koʻchasi, 86 / Gagarin St, 86).
- **AriDian** (ул. Мир Саид Барака, 65): карточка на Яндекс Картах названа
  AriDian, но ведёт на каналы Erudit, а 2ГИС указывает по этому адресу Erudit.
  Запись хранит оба названия и объясняет это в описании.
- **Сознательно нет** на сайте: рейтингов, числа отзывов и учеников, цен, наград,
  «партнёрств» и преподавателей. Фильтры по возрасту и формату скрыты, пока
  данные есть меньше чем у половины мест (`MIN_FACET_COVERAGE`), — иначе
  фильтр молча прятал бы большую часть города. В профиле строк без данных нет:
  если центр не сообщает возраст и формат, так и написано одной фразой. Возраст
  подписан «Есть группы»: источники называют группы, которые у центра есть, а
  не всех, кого он учит. Поля `priceFrom` и `rating` в типах есть и
  требуют ссылку на источник; карточки показывают их, только если они заполнены
  (сейчас — ни у одной записи).
- **Исключены**: места, закрытые по данным Яндекс Карт, агентства по учёбе за
  рубежом, записи без контактов и сведений, записи с противоречивыми данными.
- **Районы** — ориентиры с реальными координатами (Центр, Университетский
  бульвар, Гагарина и Мирзо Улугбека, Дахбед и Рудаки, Вокзал…): место
  относится к ближайшему ориентиру, границ не рисуем.

## Архитектура

```
src/
  app/          — оболочка, роутинг (страницы грузятся отдельными чанками)
  components/
    brand/      — логотип: знак и надпись, вырезанные из оригинала без перерисовки
    ui/         — примитивы дизайн-системы (Button, Chip, Dialog, Popover, …)
    layout/     — Header, MobileNav, Footer
    search/     — SearchBar и его панели, компактный поиск
    filters/    — FilterBar, FacetControl, FilterPanel, ActiveFilters, SortMenu
    centers/    — CenterCard, CenterPreviewCard, CenterLogo, Gallery, LeadDialog, CenterLink, кнопки «Избранное» и «Сравнить»
    map/        — карта: MapLibre-адаптер, маркеры, кластеры, запасное состояние
    home/       — секции главной, карусель центров
    motion/     — RevealText (слова из-под маски), RollingNumber (цифры-табло)
  admin/        — админка: вход, центры, редактор, новые центры, заявки на курсы (отдельный чанк с Supabase SDK)
  data/         — доменные типы, направления, районы, снимок центров
  services/     — centersRepository (граница данных), centerRow (строка БД ↔ запись), REST к Supabase, заявки центров, заявки на курсы
  state/        — состояние поиска (URL), избранное, сравнение, тема, тосты
  pages/        — экраны
  config/       — публичные контакты сайта, настройки Supabase из env
  map/          — конфигурация карты (стиль, границы города, атрибуция)
  styles/       — токены, базовые стили
  i18n/         — весь текст интерфейса: ru (эталон), uz (латиница), en
```

### Языки

Словари `src/i18n/{ru,uz,en}.ts` одной формы: TypeScript не соберёт проект,
если в узбекском или английском не хватает ключа. Переключение языка
перерисовывает приложение целиком и пересобирает каталог в новом языке; поиск
понимает запрос на любом из трёх («ingliz tili», «English», «английский»).
Узбекский — латиницей: `oʻ` и `gʻ` пишутся с U+02BB, апостроф (tutuq belgisi) — U+02BC.

### Карта

- `src/components/map/MapLibreMapView.tsx` — адаптер: карта MapLibre со стилем,
  подстроенным под каталог (подписи по-русски, без лишних щитов дорог), и
  собственные DOM-маркеры BilimGo. Кластеризация — своя, в экранных
  координатах; превью у маркера и контролы — в слое поверх карты.
- `MapViewProps` / `MapViewHandle` (`flyTo`, `fitMarkers`, `onViewChange`,
  `popup`, `insets`, `frame`) от провайдера не зависят.
- Во встроенных картах (главная, профиль) на телефоне карта не перехватывает
  прокрутку страницы — касание открывает полноэкранную карту; на desktop
  карта зумится колесом только с Ctrl/⌘.
- Превью на главной кадрируется по 80 % центров, ближайших к медианной точке
  (`denseCore`), поэтому окраины и аэропорт в кадр не попадают.

### Данные: Supabase или снимок

Компоненты работают только с `centersRepository`
(`src/services/centersRepository.ts`): `search`, `getById`, `getByIds`,
`getBranches`, `counts`. Каталог загружается один раз — из Supabase, если он
настроен, иначе из снимка (отдельным чанком) — и ищется в памяти, поэтому
поиск, фильтры и сортировка ведут себя одинаково с обоими источниками. После
правки в админке кэш сбрасывается (`invalidateCenters`). Отмена через
`AbortSignal`, ошибки и состояния — `?mock=slow|empty|error`.

### Состояние поиска живёт в URL

```
/search?q=english&cat=english,ielts&d=center
       &bbox=w,s,e,n&sort=center&sel=<id>&v=<lat>,<lng>,<zoom>
```

Любая ссылка воспроизводит экран целиком; «назад» отменяет фильтр.

## Дизайн-система

- **Токены** — `src/styles/tokens.css`. Палитра из логотипа: тёмно-синий
  (текст, тёмные поверхности), бирюзовый (ссылки, выбранные состояния),
  золотой из знака — только для основных действий («Найти», «Записаться»),
  текст на нём тёмно-синий. Два радиуса (8 и 16 px); тени только у плавающих
  слоёв. Весь текст ≥ 4.5:1 на своём фоне (WCAG AA).
- **Тёмная тема** — те же семантические токены, переопределённые в
  `:root[data-theme='dark']`: глубокий синий фон вместо чёрного, светлые
  «чернильные» кнопки, перекрашенная карта, светлый вариант надписи логотипа.
  Тема ставится до первой отрисовки (скрипт в `index.html`), без мигания.
- **Компоненты** — CSS Modules; состояния default / hover / active / focus /
  disabled / loading; единые фокус-кольца; увеличенные зоны нажатия на сенсорных экранах.
- **Движение** — переходы между страницами, диалоги, выбор маркера,
  «Искать в этой области». Места на карте появляются волной: чем дальше от
  центра экрана, тем позже. Текст: заголовок первого экрана и заголовки
  страниц поднимаются по словам из-под маски (`RevealText`), числа
  прокручиваются поразрядно как табло (`RollingNumber`). «Популярные центры» — карусель с фото: активная карточка в центре,
  соседние меньше; сама листается, таймер — полоска в активной точке;
  пауза при наведении, фокусе, касании, вне экрана и кнопкой (WCAG 2.2.2).
  Лента логотипов бесшовная. Только `transform` / `opacity`;
  `prefers-reduced-motion` отключает всё: текст и числа сразу на месте,
  автопрокрутки нет, лента становится статичной сеткой.
- **Шрифты** — заголовки Unbounded, текст Onest (оба variable, с кириллицей,
  self-hosted).
- **Орнамент** — сдержанная геометрия по мотивам самаркандских изразцов,
  только в фоне первого экрана главной.
